## Prerequisites

Before starting the Java Refresher, make sure you have:

- **IntelliJ IDEA** (Community or Ultimate)
- **JDK 21**
- **Git**
- A **GitHub account/repository**, if you plan to push your exercises

<div class="callout tip" markdown="1">
<div class="callout-title"><span>💡</span>You Don't Need a Separate Maven Install</div>

IntelliJ IDEA ships with **bundled Maven support**. For normal Maven projects you don't need to install Maven separately — the IDE can download and run it for you. A standalone Maven installation is only needed for things like CI servers or running Maven outside the IDE.
</div>

This course uses **JDK 21** throughout — make sure every project you create targets Java 21.

---

## 1. Install JDK 21

### Download and Install

1. Download a JDK 21 distribution (e.g. Eclipse Temurin, Oracle JDK, or Amazon Corretto).
2. Run the installer, or let IntelliJ download one for you (see [Configure IntelliJ IDEA](#2-configure-intellij-idea)).
3. Verify the installation from a terminal.

### Verify the Installation

```bash
java -version
```

```text
java version "21.x.x"
```

```bash
javac -version
```

The patch version (`21.0.x`) doesn't matter — what matters is that the major version reads **21**.

### JDK vs JRE vs JVM

- **JVM** – the virtual machine that executes bytecode.
- **JRE** – JVM + standard libraries; enough to *run* Java applications.
- **JDK** – JRE + compiler (`javac`) and development tools; what you need to *develop* Java applications.

See [Java Fundamentals](../01-java-fundamentals/#jvm-jre-jdk) for the full breakdown.

## 2. Configure IntelliJ IDEA

Point IntelliJ at JDK 21 so every new project defaults to it:

**File → Project Structure → Project**

- **Project SDK** → JDK 21 (add it via "Add SDK → Download JDK" if it isn't installed yet)
- **Language level** → 21 (or "SDK default")

<div class="callout warning" markdown="1">
<div class="callout-title"><span>⚠️</span>Keep the IDE and Maven JDK Aligned</div>

The JDK configured here in Project Structure and the JDK Maven actually uses to build your project need to match. See [Configure Maven in IntelliJ](#8-configure-maven-in-intellij) — mismatches here are a common source of confusing build errors.
</div>

---

## 3. Create a Maven Project

**Maven** is a build and dependency management tool used to compile, test and package Java applications and manage their dependencies.

1. Open IntelliJ IDEA.
2. Select **New Project**.
3. Choose **Maven** as the build system.
4. Select **JDK 21** as the project JDK.
5. Give the project a **name** (e.g. `java-refresher`).
6. Choose the project **location**.
7. Click **Create**.

IntelliJ generates the standard Maven folder layout and an initial `pom.xml` for you.

---

## 4. Maven Project Structure

```text
my-java-project/
├── pom.xml
├── src/
│   ├── main/
│   │   └── java/
│   │       └── ...
│   └── test/
│       └── java/
│           └── ...
└── target/
```

- **`pom.xml`** – the Maven project configuration: dependencies, plugins, build settings.
- **`src/main/java`** – your production Java source code.
- **`src/test/java`** – your test source code.
- **`target`** – generated build output (compiled classes, jars, reports).

<div class="callout warning" markdown="1">
<div class="callout-title"><span>⚠️</span>Never Commit target/</div>

`target/` is entirely regenerated by Maven on every build — it should never be committed to Git. See [Git Setup](#12-git-setup).
</div>

---

## 5. The pom.xml

A minimal, modern `pom.xml` targeting Java 21:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0
         https://maven.apache.org/xsd/maven-4.0.0.xsd">

    <modelVersion>4.0.0</modelVersion>

    <groupId>com.example</groupId>
    <artifactId>java-refresher</artifactId>
    <version>1.0-SNAPSHOT</version>

    <properties>
        <maven.compiler.release>21</maven.compiler.release>
        <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
    </properties>

</project>
```

- **`groupId`** – identifies your organization/group (reverse-domain style, e.g. `com.example`).
- **`artifactId`** – the name of the project/jar produced.
- **`version`** – the project's version (`-SNAPSHOT` marks it as in-development).
- **`maven.compiler.release`** – tells Maven which Java release to compile *against*:

```xml
<maven.compiler.release>21</maven.compiler.release>
```

Without this property, Maven falls back to an older default compiler target, even if your JDK itself is 21.

## 6. Maven Wrapper

The **Maven Wrapper** lets developers build the project with a project-defined Maven version, without requiring Maven to be installed globally. It adds these files to your project:

```text
mvnw
mvnw.cmd
.mvn/
```

Run it instead of a globally installed `mvn`:

**Windows:**
```bash
mvnw.cmd --version
```

**Unix/macOS:**
```bash
./mvnw --version
```

<div class="callout tip" markdown="1">
<div class="callout-title"><span>💡</span>Prefer the Wrapper</div>

When `mvnw`/`mvnw.cmd` are committed to a project, prefer them over a globally installed `mvn` — they guarantee every developer (and CI) builds with the exact same Maven version.
</div>

## 7. Verify Maven + Java

Confirm Maven itself is using JDK 21:

```bash
mvn --version
```

or, using the wrapper:

```bash
mvnw.cmd --version
```

The output shows the **Maven version**, the **Java version**, and the **Java home** path in use. The Java version here should read **21**.

<div class="callout warning" markdown="1">
<div class="callout-title"><span>⚠️</span>java -version Is Not the Same Check</div>

It's entirely possible for `java -version` on your PATH to show Java 21 while Maven is actually building with a *different* JDK (e.g. one pinned via `JAVA_HOME` or IntelliJ's own settings). Always check the Java version reported by `mvn --version` itself, not just your terminal's `java -version`.
</div>

## 8. Configure Maven in IntelliJ

**Settings → Build, Execution, Deployment → Build Tools → Maven**

- **Maven home path** – bundled Maven (default) or a path to your own installation.
- **JDK for importer** – the JDK IntelliJ uses to read/import the project → set to **21**.
- **Runner → JRE** *(under the Maven → Runner settings)* – the JDK used to actually run Maven goals → set to **21**.

Keeping both aligned with the project's `maven.compiler.release` avoids the "works in IntelliJ but not on the command line" (or vice versa) class of problems.

## 9. Create a First Java Class

Create `src/main/java/com/example/Main.java`:

<div class="callout warning" markdown="1">
<div class="callout-title"><span>⚠️</span>Already Generated by IntelliJ?</div>

If IntelliJ generated the project for you, a `Main` class with a `main` method may already exist under `src/main/java/yourpackagename`. Use that file instead of creating a new one — just make sure its contents match the example below.
</div>

```java
package com.example;

public class Main {

    public static void main(String[] args) {
        System.out.println("Hello, Java 21!");
    }
}
```

Right-click the file (or the green gutter arrow next to `main`) and choose **Run 'Main.main()'**.

**Expected output:**

```text
Hello, Java 21!
```

## 10. Run the Project with Maven

Standard Maven lifecycle commands:

```bash
mvn clean
mvn compile
mvn test
mvn package
```

- **`clean`** – deletes the `target/` directory.
- **`compile`** – compiles `src/main/java` into `target/classes`.
- **`test`** – compiles and runs tests in `src/test/java`.
- **`package`** – builds a distributable jar (or war) into `target/`.

Wrapper equivalent:

```bash
mvnw.cmd clean test
```

## 11. Add a Simple Test

Add JUnit 5 to `pom.xml`:

```xml
<dependency>
    <groupId>org.junit.jupiter</groupId>
    <artifactId>junit-jupiter</artifactId>
    <version>5.11.0</version>
    <scope>test</scope>
</dependency>
```

Create `src/test/java/com/example/MainTest.java`:

```java
import org.junit.jupiter.api.Test;

import static org.junit.jupiter.api.Assertions.assertEquals;

class MainTest {

    @Test
    void shouldReturnExpectedValue() {
        assertEquals(4, 2 + 2);
    }
}
```

Run it with `mvn test`, or via the green gutter arrow next to the test method in IntelliJ.

## 12. Git Setup

`.gitignore`:

```gitignore
target/
.idea/
*.iml
```

- **Commit:** source code (`src/`), `pom.xml`, and the Maven Wrapper files (`mvnw`, `mvnw.cmd`, `.mvn/`).
- **Don't commit:** build output (`target/`) and IDE-specific files (`.idea/`, `*.iml`) — unless the team explicitly decides to share IDE settings.

## 13. Troubleshooting

### "java -version shows the wrong version"

`JAVA_HOME` or the system `PATH` may point at a different JDK than the one you expect. Check `echo %JAVA_HOME%` (Windows) or `echo $JAVA_HOME` (Unix/macOS), and check which `java` executable is first on your `PATH`.

### "Maven uses the wrong Java version"

Run `mvn --version` and check the reported Java version and Java home. Then check IntelliJ's **JDK for importer** and **Runner → JRE** settings ([step 8](#8-configure-maven-in-intellij)).

### "Cannot resolve Maven dependencies"

- Reload the Maven project (Maven tool window → refresh icon).
- Check your internet connection.
- Check that Maven's remote repositories are reachable.
- Double-check `pom.xml` for typos in `groupId`/`artifactId`/`version`.

### "Project language level is wrong"

**File → Project Structure → Project → Language Level** — make sure it's set to 21 (or "SDK default" with a 21 SDK selected).

### "IntelliJ does not recognize Maven"

Open the **Maven** tool window and click **Reload All Maven Projects** to force a re-import.
